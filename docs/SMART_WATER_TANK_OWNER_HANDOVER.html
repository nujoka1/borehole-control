1. Purpose of this document

This guide gives the system owner the information needed to operate and administer the Smart Water Tank system responsibly. It covers the web dashboard, Android application, ESP32 controller, Supabase backend, account management, automatic pump thresholds, security, maintenance and support handover.

Important: Software builds and automated tests have passed, but the physical ESP32, ultrasonic sensor, relay, contactor and pump installation must still be commissioned and verified on the real hardware by competent personnel.

2. System summary

Smart Water Tank monitors the water level in a storage tank and automatically controls filling. An ultrasonic sensor reports the distance to the water surface. The ESP32 converts this distance to tank level, applies safety checks and controls the relay command.

The system consists of:

  • ESP32 firmware: measures tank level and performs local automatic pump decisions.
  • Ultrasonic sensor: measures the distance between the sensor and water surface.
  • Relay/contactor interface: receives the ESP32 pump command; it must be correctly isolated and electrically rated.
  • Supabase backend: provides authentication, authorization, telemetry storage, alerts, settings and device communication.
  • Web dashboard: provides browser-based monitoring and administration.
  • Android APK: packages the same dashboard functions for an Android phone.

4. What the owner can do

  • Sign in securely using the assigned owner account.
  • View live tank level, water height, pump state and device connectivity.
  • Review recent readings, alerts, activity and configuration delivery.
  • Configure the lower limit, upper limit and usable tank depth.
  • Create Viewer or Operator accounts and assign them to the tank.
  • Use light or dark appearance and access the built-in guidance pages.
Automatic-only design: The application does not provide manual pump ON/OFF controls or a control-mode switch. This is intentional. The ESP32 remains responsible for automatic control and safety interlocks.

5. Automatic pump operation

The controller uses two thresholds to prevent rapid switching:

  • Lower limit: when the level falls to or below this value, the ESP32 may start filling after validating the sensor and safety state.
  • Upper limit: when the level reaches this value, the ESP32 stops filling.

The standard starting values are 60% for the lower limit and 95% for the upper limit. The two limits must remain at least five percentage points apart. The correct values should be selected based on the real tank, water demand and pump installation.

Local ESP32 operation does not depend on continuous internet access. If Wi-Fi or Supabase is temporarily unavailable, live monitoring stops, but the controller can continue its local automatic logic. Sensor failure, stale measurements and maximum runtime conditions request a safe pump-OFF state.

6. Dashboard and Android application

Home

Shows tank percentage, calculated water height, pump status, lower and upper limits, latest update time and overall system status.

History

Shows recent tank readings and trends. A history value is evidence of data received by the backend; it is not a substitute for checking the physical tank when readings appear abnormal.

Alerts

Shows sensor faults, device events and configuration delivery results. Repeated faults should be investigated rather than repeatedly cleared or ignored.

Settings

Allows threshold and tank-depth configuration, appearance selection, user creation, guidance, application information and sign-out.

Installing the APK

  1. Copy Smart-Water-Tank-v1.0.apk to the Android phone through a trusted private channel.
  2. Allow installation from the selected file manager when Android requests permission.
  3. Install the APK, open Smart Water Tank and sign in.
  4. Disable the temporary “install unknown apps” permission afterward if it is no longer required.

The supplied APK is debug-signed for direct installation. Publishing through Google Play requires an owner-controlled release signing key, a release build and store compliance preparation.

7. Creating and managing users

Only a tank owner can create a user. In the application, open Settings → Create user, then enter the full name, email address, temporary password and access level.

RoleIntended access
OwnerSystem administration and ownership. The existing owner role is managed deliberately and is not offered in the routine user-creation form.
OperatorMonitoring plus permitted automatic configuration such as tank thresholds.
ViewerMonitoring access without configuration authority.

After creation, Supabase attempts to send a secure one-time sign-in link. The email is optional: the new user can ignore it and sign in using the temporary password. If mail delivery is unavailable, the account is still created and the application tells the owner to share the temporary password privately.

Good practice: Give every person an individual account. Do not share the owner password. Remove access promptly when a person no longer needs the system.

8. Wi-Fi setup and recovery

The ESP32 first tries its configured Wi-Fi network. If it cannot connect, it can open a temporary setup network named Smart-Water-Tank-xxxx. Connect a phone to that network and use the captive portal to select the installation Wi-Fi.

If the device appears offline:

  1. Confirm the ESP32 has stable power.
  2. Confirm the router and internet connection are available.
  3. Confirm the configured Wi-Fi network is within range.
  4. Check the status LED and Serial Monitor at 115200 baud if technical diagnosis is required.
  5. Do not assume “offline” means local automatic control has stopped.

9. ESP32 firmware handover

The owner or technician should copy the complete Smart_Water_Tank_Arduino folder. The folder and its main file Smart_Water_Tank_Arduino.ino must keep matching names.

Arduino IDE requirements:

  • Board package: esp32 by Espressif Systems 3.3.11
  • Board selection: ESP32 Dev Module
  • Library: ArduinoJson 7.4.2
  • Library: WiFiManager 2.0.17
  • Serial Monitor: 115200 baud
Private file: The folder contains secrets.h, which holds the device credential and endpoints. Never publish this file on GitHub or send it through a public channel. Each future controller should have a separate device code and token.

  • Do not power a pump or contactor coil directly from an ESP32 GPIO.
  • Use a correctly rated and isolated relay/driver interface.
  • Limit a 5 V ultrasonic ECHO output to an ESP32-safe input voltage.
  • Provide correctly rated breaker, overload protection, contactor, earthing and cabling.
  • Use a moisture-resistant enclosure with cable protection and strain relief.
  • Mains-voltage work must be completed or inspected by a qualified electrician.

11. Commissioning checklist

  1. Verify continuity and absence of power-rail shorts with power disconnected.
  2. Power only the low-voltage controller and measure supply and ECHO voltages.
  3. Verify sensor distance readings at several known water depths.
  4. Confirm configured usable tank depth and sensor mounting offset.
  5. Test relay polarity without connecting the pump.
  6. Test automatic lower-limit start and upper-limit stop safely.
  7. Disconnect the sensor and confirm the relay command goes OFF.
  8. Disconnect Wi-Fi and confirm local automatic behavior.
  9. Commission the actual contactor and pump under qualified supervision.
  10. Record the final thresholds, measured voltages, relay polarity and test results.

12. Security and ownership responsibilities

  • Protect the owner email account with a strong unique password and multi-factor authentication where available.
  • Enable Supabase leaked-password protection and configure production SMTP for reliable mail delivery.
  • Keep Supabase secret/service-role keys out of browsers, APKs, firmware and public repositories.
  • Rotate a device token if it is exposed, then update both the database hash and private firmware configuration.
  • Review users and device memberships periodically.
  • Keep backups of source code, database configuration, signing keys and installation records.
  • Keep the GitHub repository and Supabase project under accounts controlled by the owner or an agreed organization.
